# GEOスコアリングツール v2.0 設計書
## 自己進化型ナレッジループ - アーキテクチャ設計

**作成日**: 2026-04-09
**バージョン**: 2.0 (Draft)
**目的**: AI検索エンジンにおけるブランド言及率（SOV）と推奨度スコアの最大化

---

## 1. システム進化の概要

### 1.1 v1.0（現行システム）の特徴

| 機能 | 実装状況 |
|------|---------|
| スコアリング | 4指標（認知、推奨度、ポジション、正確性） |
| データ収集 | Gemini API経由でAI回答を取得 |
| 分析 | 手動設定のプロンプトで定期評価 |
| 可視化 | Streamlitダッシュボード（3画面） |
| データベース | SQLite（ローカル） |
| 自動化 | 週次/月次バッチ処理 |

### 1.2 v2.0への進化ポイント

```
v1.0: スコア測定ツール
  ↓
v2.0: 自己進化型インテリジェンスプラットフォーム
```

| 進化領域 | v1.0 | v2.0 |
|---------|------|------|
| **思考解析** | なし | LLMの推論プロセスをリバースエンジニアリング |
| **引用追跡** | なし | AIが参照したソースを特定・分析 |
| **技術監査** | なし | SEO/GEO両面の技術基盤を自動監視 |
| **自律改善** | なし | ギャップ検出→施策提案→効果測定のループ |
| **外部連携** | Geminiのみ | Serp API, Ahrefs, Screaming Frog, MCP |
| **データ基盤** | SQLite | BigQuery + Google Sheets統合 |
| **ビジネス** | 自社利用 | 代理店向けOEMモデル |

## 2. システムアーキテクチャ

### 2.1 全体構成図

```
┌─────────────────────────────────────────────────────────────┐
│                    v2.0 アーキテクチャ                        │
└─────────────────────────────────────────────────────────────┘

┌──────────────┐     ┌──────────────┐     ┌──────────────┐
│  外部API層   │────▶│ エージェント層│────▶│  データ層     │
└──────────────┘     └──────────────┘     └──────────────┘
  ↓ Serp API          ↓ Gem_01〜05         ↓ BigQuery
  ↓ Ahrefs MCP        ↓ Orchestrator       ↓ Google Sheets
  ↓ Screaming Frog    ↓ HITL Manager       ↓ SQLite (Cache)
  ↓ Gemini API
                      ↓
              ┌──────────────┐
              │  UI/UX層     │
              └──────────────┘
                ↓ Streamlit
                ↓ Google Chat
                ↓ Google Docs
```

### 2.2 レイヤー別の責務

#### Layer 1: 外部API統合層
- **役割**: 各種データソースとの接続
- **実装**: API Client モジュール群
- **技術**: REST API, MCP (Model Context Protocol), WebDriver

#### Layer 2: インテリジェンスエージェント層
- **役割**: 5つの専門エージェント（Gem_01〜05）による分析・実行
- **実装**: Claude Code Agent SDK
- **技術**: LangChain, Task Delegation, State Management

#### Layer 3: データ統合層
- **役割**: 構造化データの保存・クエリ
- **実装**: BigQuery Schema + Google Sheets Sync
- **技術**: SQLAlchemy (ORM), BigQuery API, Google Sheets API

#### Layer 4: ヒューマンインターフェース層
- **役割**: 人間の判断・承認・修正を組み込む
- **実装**: Streamlit + Google Workspace連携
- **技術**: Streamlit, Google Chat Bot, Google Docs API

## 4. マイクロエージェント詳細設計

### 4.1 Gem_01: GEO_Intelligence_Analyst

**役割**: LLMの思考プロセスと参照ソースのリバースエンジニアリング

#### Input
```python
{
  "target_query": "マーケティングツール おすすめ",
  "competitor_domains": ["competitor-a.com", "competitor-b.com"],
  "serp_api_results": {...}  # AIO検索結果
}
```

#### Processing Logic
1. **思考トレース抽出**
   - ChatGPT Thinkingモデルを使用してAIの推論プロセスを可視化
   - どのような情報を「重要」と判断したかを言語化

2. **参照ソース特定**
   - AIが内部的に検索した可能性のあるクエリを推測
   - 実際に参照されたURLを抽出

3. **権威性評価**
   - Ahrefs MCPを使用してDR（Domain Rating）を取得
   - 「なぜこのサイトが選ばれたか」の仮説構築

#### Output
```python
{
  "query_id": "q_20260409_001",
  "thought_trace": {
    "steps": [...],
    "key_insights": [
      "AIは「導入実績」を重視している",
      "競合Aは「価格の明瞭性」で優位"
    ]
  },
  "citation_analysis": [
    {
      "entity": "競合A社",
      "mention_count": 3,
      "sentiment": 0.7,
      "authority_sources": [
        {"url": "review-site.com", "dr": 85}
      ]
    }
  ],
  "recommendation": "自社も「導入実績」の可視化が必要"
}
```

#### 実装技術スタック
- **LLM**: Claude Sonnet 4.5 (Thinking Mode)
- **API**: Serp API, Gemini API
- **MCP**: Ahrefs MCP
- **データ保存**: BigQuery (LLM_Thought_Log, Citation_Master)

### 4.2 Gem_02: Gap_Strategist_v2

**役割**: 技術的SEOとコンテンツ的GEOの両面からギャップを特定し、優先順位付きロードマップを生成

#### Input
```python
{
  "llm_thought_log": {...},  # Gem_01の分析結果
  "technical_audit": {...},  # Screaming Frogデータ
  "current_rankings": {...}  # GRCの順位データ
}
```

#### Processing Logic
1. **コンテンツギャップ分析**
   - 「AIが参照した競合サイトにあって自社にない要素」を列挙
   - 例: 導入実績ページ、料金比較表、FAQ

2. **技術ギャップ分析**
   - 構造化データの不足（Product, FAQ, HowTo等）
   - インデックス問題（noindex誤設定、クロールエラー）
   - パフォーマンス問題（ページ速度、モバイル対応）

3. **優先順位付け**
   - Impact（影響度） × Effort（工数）のマトリクス
   - Quick Wins（即効性の高い施策）を最優先

#### Output
```python
{
  "gap_analysis_id": "gap_20260409_001",
  "content_gaps": [
    {
      "gap": "導入実績ページが存在しない",
      "competitor_has": ["競合A社", "競合B社"],
      "priority": "P0",
      "estimated_impact": "High"
    }
  ],
  "technical_gaps": [
    {
      "gap": "FAQ構造化データが未実装",
      "affected_pages": 15,
      "priority": "P1",
      "fix_effort": "Low"
    }
  ],
  "roadmap": [
    {
      "task_id": "task_001",
      "description": "導入実績ページの作成",
      "assigned_to": "Gem_03",
      "due_date": "2026-04-16",
      "status": "Pending"
    },
    {
      "task_id": "task_002",
      "description": "FAQ構造化データの実装",
      "assigned_to": "Gem_04",
      "due_date": "2026-04-12",
      "status": "Pending"
    }
  ]
}
```

#### 実装技術スタック
- **分析**: Pandas, NumPy
- **優先順位付け**: カスタムロジック（Impact × Effort）
- **データ保存**: BigQuery (Roadmap_Registry)

### 4.5 Gem_05: Echo_Monitor

**役割**: 配信後のエコー（AI検索結果への反映）を監視し、フィードバックループを回す

#### Input
```python
{
  "published_content_ids": ["content_20260409_001", ...],
  "monitoring_queries": ["マーケティングツール", ...]
}
```

#### Processing Logic
1. **エコー検出**
   - 配信から72時間後にSerp APIで再検索
   - 自社コンテンツが引用されているかを確認

2. **センチメント変化の追跡**
   - 配信前後のSentiment_Scoreを比較
   - ポジティブな変化があれば成功

3. **ループバック判定**
   - エコーなし → Gem_01に戻って再分析
   - エコーあり → 関連コンテンツの追加配信をトリガー

#### Output
```python
{
  "echo_report_id": "echo_20260412_001",
  "content_id": "content_20260409_001",
  "echo_detected": True,
  "citations": [
    {
      "query": "マーケティングツール 導入実績",
      "llm": "Gemini",
      "citation_text": "XXは1000社の導入実績を持つ..."
    }
  ],
  "sentiment_change": {
    "before": 0.3,
    "after": 0.6,
    "delta": +0.3
  },
  "next_action": "trigger_related_content"  # または "loop_back_to_gem_01"
}
```

#### 実装技術スタック
- **監視**: Serp API, Gemini API
- **スケジュール**: APScheduler (72時間後実行)
- **データ保存**: BigQuery (Content_Registry, Citation_Master)

## 5. オーケストレーションフロー

### 5.1 Phase 1: Reverse Engineering（逆算分析）

```
[Trigger: 週次実行 or 競合スコア急上昇検知]
    ↓
[Gem_01] ターゲットクエリでAI検索を実行
    ↓
[Gem_01] AIの思考プロセスをトレース
    ↓
[Gem_01] 参照ソースを特定（Ahrefs MCPでDR取得）
    ↓
[Output] LLM_Thought_Log, Citation_Master に保存
```

### 5.2 Phase 2: Double-Track Execution（並列実行）

```
[Input: Gem_01の分析結果]
    ↓
[Gem_02] ギャップ分析を実行
    ↓
   ┌─────────────┴─────────────┐
   ↓                            ↓
[Track A: Technical]      [Track B: Content]
   ↓                            ↓
[Gem_04]                     [Gem_03]
構造化データ修正              コンテンツ生成
インデックス最適化            Google Docs出力
   ↓                            ↓
[Output]                     [HITL承認待ち]
engineer_instructions        Google Chat通知
   ↓                            ↓
[人間承認]                   [人間承認・修正]
   ↓                            ↓
[実装完了]                   [配信実行]
```

### 5.3 Phase 3: Feedback Loop（循環）

```
[配信完了]
    ↓
[72時間待機]
    ↓
[Gem_05] エコー測定を実行
    ↓
   ┌──────────┴──────────┐
   ↓                      ↓
[エコーなし]          [エコー検出]
   ↓                      ↓
[Gem_01へループバック]  [関連コンテンツ配信]
再分析                   SNS拡散等
```

## 6. Human-in-the-Loop (HITL) プロトコル

### 6.1 承認ポイント

| フェーズ | 承認内容 | インターフェース |
|---------|---------|----------------|
| **戦略合意** | Gem_02のロードマップ | Streamlit Dashboard |
| **コンテンツ品質** | Gem_03の生成文書 | Google Docs + Google Chat |
| **技術変更** | Gem_04の修正指示 | Google Sheets + Slack |

### 6.2 Google Chat統合

**承認フロー例**:
```
[Google Chat Bot]
📝 新しいコンテンツが作成されました

タイトル: 導入実績1000社突破！
作成者: Gem_03
確認URL: https://docs.google.com/.../edit

[承認] [修正依頼] [却下]
```

ボタンクリック後:
- **承認**: Content_Registryのステータスを"Approved"に更新 → 配信API実行
- **修正依頼**: 担当者に通知、Google Docsで編集
- **却下**: ステータスを"Rejected"に更新、理由をログ

**base_client.py の設計**:
```python
from abc import ABC, abstractmethod
from typing import Any, Dict
import tenacity

class BaseAPIClient(ABC):
    def __init__(self, api_key: str, base_url: str):
        self.api_key = api_key
        self.base_url = base_url

    @tenacity.retry(
        wait=tenacity.wait_exponential(min=1, max=60),
        stop=tenacity.stop_after_attempt(3)
    )
    @abstractmethod
    def _request(self, endpoint: str, params: Dict[str, Any]) -> Dict:
        """API呼び出しの基盤メソッド"""
        pass
```

## 8. 代理店向けOEMインフラ

### 8.1 マルチテナント設計

```
┌─────────────────────────────────────────┐
│  プラットフォーム（我々が運営）          │
└─────────────────────────────────────────┘
              ↓
   ┌──────────┴──────────┐
   ↓                      ↓
[代理店A]              [代理店B]
 ├ クライアント1        ├ クライアント1
 ├ クライアント2        ├ クライアント2
 └ ...                  └ ...
```

**テナント分離**:
- BigQueryで`agency_id`によるパーティショニング
- Google Sheetsは代理店ごとに専用フォルダ
- Streamlitは`?agency=xxx`でビューを切り替え

### 8.2 収益モデル

| 項目 | 金額（例） |
|------|-----------|
| **代理店の月額利用料** | 30万円 |
| **代理店がクライアントに請求** | 20万円/社 × 10社 = 200万円 |
| **代理店の粗利** | 200万円 - 30万円 = **170万円** |
| **我々の収益** | 30万円/代理店 × N代理店 |

**API コスト例**:
- Serp API: $50/月
- Ahrefs: $99/月
- Screaming Frog: $149/月
- BigQuery: $50/月
- **合計**: 約$350/月（≒4.5万円）

→ 利益率: (30万円 - 4.5万円) / 30万円 = **85%**
